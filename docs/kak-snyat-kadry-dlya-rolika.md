# Как снять кадры для обучающего ролика

Памятка для съёмки пяти скриншотов, из которых собирается ролик про приложение
жителей. Снимает человек своим Android-телефоном; кадры кладутся в
`public/shots/` проекта `skaz-video` под точными именами из таблицы ниже.

Раскадровка и назначение каждого кадра — в
[спеке ролика](superpowers/specs/2026-09-23-obuchayushchiy-rolik-app-design.md).

## Главное правило: передавать файлом

Telegram пережимает картинки, отправленные как фото: скриншот 1080×2340
превращается в 591×1280. Ролик из таких кадров получается мыльным.

Отправлять так:

- **из чата:** скрепка → **«Файл»** (не «Галерея») → `Pictures/Screenshots`;
- **из галереи:** «Поделиться» → Telegram → снять галочку сжатия;
- признак успеха: в чате приходит карточка с именем файла и размером 1–3 МБ, а
  не картинка-превью.

Годятся и другие пути: положить в Google Drive, скинуть кабелем.

## Остальные правила

- **Один телефон, одна вертикальная ориентация, один масштаб шрифта.** Если
  между кадрами поменять в настройках Android размер шрифта, поедут пропорции —
  разметку наездов придётся делать заново.
- **Никаких помех в кадре:** открытая клавиатура, шторка уведомлений,
  всплывающее уведомление, выделенный текст, нажатое состояние кнопки.
- **Строку состояния оставляем** — часы и батарея делают кадр честным.
- **Прокрутка такая, чтобы объект наезда был целиком в кадре** и не прижимался к
  верхнему или нижнему краю.

Само приложение всегда светлое: в его стилях нет тёмной темы и оно не
подхватывает `themeParams` Telegram. Тёмной темой отличается только первый
кадр — экран группы. Это нормально: переход из тёмного Telegram в светлое
приложение в ролике читается.

## Кадры

### `01-zakrep.png` — группа жителей со ссылкой

Открытая группа, прокрученная так, чтобы в кадр попали **и полоса закреплённого
сообщения** под шапкой, **и само сообщение со ссылкой** на приложение. Одним
снимком закрываются оба шага: в ролике по нему идут два наезда подряд.

Наезд идёт на сообщение со ссылкой, а не на полосу закрепа: полоса может
показывать другой закреп, и подсветка увела бы внимание не туда.

### `02-glavnyy.png` — главный экран приложения

`/poselenie/app`, прокручен в самое начало. В кадре: шапка мини-приложения,
название поместья, карточка дневника, плитки разделов.

Наезд идёт на верх экрана — шапку и карточку дневника. Если в дневнике висит
«Пробная запись», лучше сперва опубликовать настоящую: на наезде эта строка
читается.

### `03-yarmarka.png` — ярмарка

Раздел «Товары и услуги соседей» со списком живых объявлений: хотя бы два-три
товара с фотографиями и ценами.

Наезд идёт на верхнюю карточку товара.

### `04-obshchiy-dom.png` — общий дом

Раздел с тремя блоками в кадре: «Бронирование помещений», «Отчёт о расходах»,
«Протоколы встреч Попечительского совета». Все три должны попасть в кадр — титр
обещает бронь и протоколы.

Наезд идёт на кнопку бронирования.

### `05-sosedi.png` — соседи

«Наши соседи», справочник: поляны с числом участков. Если идёт анимация
«Открываем поляну…», дождитесь её окончания и снимайте готовый экран.

Наезд идёт на верхнюю поляну.

## Чего в ролике больше нет

Инструменты, книги и поездки снимать не нужно: на момент съёмки разделы были
пусты («Каталог пуст», «Пока нет предстоящих поездок»), и сцены про них убраны.
Когда наполнятся — вернутся отдельными короткими роликами, и тогда кадры
понадобятся.

## После съёмки

Кадры кладутся в `public/shots/` проекта `skaz-video`, затем:

```bash
npm run scan    # перечитать размеры кадров
npm run check   # проверить, что сценарий ссылается на существующие файлы
```

Если размеры кадров изменились (пришли оригиналы вместо черновиков),
координаты наездов в `src/scenario.ts` пересчитываются пропорционально: новая
ширина делится на старую, все четыре числа каждого прямоугольника умножаются на
этот коэффициент.
