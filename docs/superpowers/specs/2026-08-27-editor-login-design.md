# Вход в Decap CMS для редактора без GitHub-аккаунта

## Проблема

Единственный вход в Decap CMS (`/admin/#/`) — через GitHub OAuth (self-hosted прокси, см. `docs/` в основном репозитории abconsult-app / память сессии). У редактора, которому нужно только добавлять заметки в раздел «Новости», нет и не должно быть GitHub-аккаунта — у него есть только email.

## Решение

Второй, независимый вход `/editor/` на git-gateway backend Decap CMS через Netlify Identity. Существующий `/admin/` (GitHub OAuth) не меняется.

### Почему Netlify Identity + Git Gateway, а не самописный прокси

- Официально поддерживаемый Decap CMS способ авторизации редакторов без GitHub-аккаунта.
- Бесплатный сервис используется только как модуль логина — сам сайт остаётся на нашем сервере, хостинг с Netlify не используется.
- Zero custom code для аутентификации/отправки писем — значит не нужно строить свою отправку email на сервере, где уже есть задокументированная проблема репутации почты (SPF/DKIM на этом же сервере, см. память `email_gmail_spf_dkim_reject`).
- Даёт ровно нужный UX «из коробки»: приглашение по email → редактор сам задаёт пароль → дальше вход логин+паролем, без писем на каждый вход.

### Компоненты

1. **`public/editor/index.html`** — отдельная HTML-страница Decap CMS (аналог `public/admin/index.html`), подключает `netlify-identity-widget.js` и указывает на `config.yml` в той же папке.
2. **`public/editor/config.yml`** — сгенерированный конфиг:
   - `backend: { name: git-gateway, branch: main }`
   - `identity_url: https://<netlify-site-name>.netlify.app/.netlify/identity` — точное значение подставляется после того, как пользователь создаст Netlify-сайт
   - единственная коллекция — «Новости» (те же поля, что в текущей `novosti` коллекции основного конфига: title, date, body, скрытая категория `novosti`)
3. **`scripts/gen-editor-config.mjs`** — генератор `public/editor/config.yml`, отдельный от `scripts/gen-decap-config.mjs` (тот отвечает только за `/admin/`). Оба читают `src/data/categories.js` при необходимости, но `editor` не нуждается в списке рубрик — только в схеме полей коллекции «Новости», которую держим в одном месте и импортируем в оба генератора, чтобы поля не разъезжались при правке.
4. **Netlify-сайт** (заводит пользователь сам, вне моей зоны действия — создание стороннего аккаунта):
   - Регистрация в Netlify (бесплатный план)
   - Новый сайт — можно импортировать тот же GitHub-репозиторий `digistaff-team/skaz-kray-astro` (хостинг с него использовать не будем, нужен только сам факт существования сайта для Identity-эндпоинта)
   - Site settings → Identity → Enable Identity
   - Identity → Registration preferences → **Invite only**
   - Identity → Services → Git Gateway → Enable Git Gateway → авторизовать доступ к GitHub-репозиторию
   - Identity → Invite users → email редактора

### Границы ответственности и безопасность

- Git Gateway не поддерживает ограничение прав по папкам/коллекциям на уровне git — редактор физически может закоммитить куда угодно в репозитории через API Git Gateway, интерфейс `/editor/` лишь не показывает других коллекций. Для единственного доверенного редактора это принятый, стандартный для Decap CMS компромисс — не жёсткая ACL-граница.
- Секретов на нашем сервере не добавляется: токен для Git Gateway хранится и управляется целиком на стороне Netlify.
- Автодеплой (`skaz-kray-autodeploy.sh`) синхронизирует `public/editor/` как обычную часть сборки Astro (`dist/editor/`) — никаких дополнительных `--exclude` не требуется, в отличие от `oauth/` (там были серверные секреты, здесь их нет).

### Что не меняется

- `/admin/` и его self-hosted OAuth-прокси (`oauth/auth.php`, `oauth/callback.php`, `oauth/config.php`) остаются как есть.
- Основной `public/admin/config.yml` и `scripts/gen-decap-config.mjs` не трогаем.

## Проверка (после реализации)

1. `npm run build` включает `dist/editor/index.html` и `dist/editor/config.yml`.
2. После деплоя (автодеплой, до 10 минут) `https://skaz-kray.ru/editor/` открывается и просит войти через Identity-виджет (не GitHub).
3. Пользователь настраивает Netlify-сайт и приглашает редактора — вход и публикация заметки проверяются вручную редактором/пользователем.
