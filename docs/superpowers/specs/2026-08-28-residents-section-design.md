# Раздел для жителей поселения — дизайн

**Дата:** 2026-08-28
**Проект:** skaz-kray.ru
**Статус:** утверждён к реализации

## Задача

Добавить на skaz-kray.ru раздел для жителей поселения с авторизацией по email и паролю
(отдельный аккаунт на каждую семью). В личном кабинете семья ведёт дневник своего
поместья и выкладывает свои товары и услуги. Заметки после проверки редактором
публикуются в разделе «Дневники поместий», товары и услуги — в разделе «Ярмарка».
Обе публичные ленты видны любому посетителю сайта; писать и попадать в кабинет
можно только по входу.

## Решения по требованиям

- **Модерация:** любой пользовательский контент (заметка, товар) уходит редактору на
  проверку и публикуется только после одобрения.
- **Регистрация:** гибридная — семья подаёт заявку (email, пароль, название поместья),
  администратор/редактор её одобряет, после чего аккаунт активируется.
- **«Поместье»:** публичных страниц-профилей поместий нет. Есть две общие публичные
  ленты — «Дневники поместий» (записи вперемешку, подписаны семьёй) и «Ярмарка»
  (товары и услуги). Кабинет приватный.
- **Масштаб:** до ~30 семей, редкие записи. Оправдано лёгкое решение.
- **Email:** используется почтовый ящик на домене skaz-kray.ru с доступом по SMTP
  (реквизиты предоставляются на этапе внедрения). Полноценные email-флоу
  (подтверждение/уведомления/восстановление пароля) со страховкой ручного сброса
  пароля редактором.
- **Роли:** «житель» (семья) и «редактор» (модератор — тот же человек, что правит сайт
  через `/editor/`).

## Архитектура

Подход: маленькое динамическое PHP-приложение рядом со статическим сайтом
(отвергнуты: «всё через git-коммиты» — не тянет многопользовательский модерируемый
UGC; отдельное Next.js в контейнере — избыточно для 30 семей).

- **Публичный статический сайт (Astro)** остаётся без изменений, кроме пунктов меню
  в шапке.
- **PHP-приложение** на уже работающем `php8.3-fpm`, чистый PHP + PDO, тонкий роутер,
  шаблоны-партиалы. Без тяжёлого фреймворка — соответствует существующим PHP-прокси
  на сервере и духу «легко и просто».
- **Размещение — вне докрута статики:** отдельный каталог `/var/www/skaz-residents/`.
  Это критично: автодеплой статики (`skaz-kray-autodeploy.sh`, cron каждые 10 мин)
  делает `rsync --delete` по докруту Astro. Приложение вне докрута этот процесс
  не затрагивает.
- **База данных:** отдельная база `skazkray_residents` в той же MariaDB, отдельный
  пользователь БД с ограниченными правами. Не смешивается с `wordpress_db`.
- **nginx:** отдельные `location`-блоки в vhost skaz-kray.ru, fastcgi на
  `unix:/run/php/php8.3-fpm.sock`, `root`/`alias` на каталог приложения.

### Стиль

Шаблоны PHP используют дизайн-токены сайта (зелёный `#008757`, охристый акцент
`#c98a3a`, PT Serif / PT Sans) — раздел визуально неотличим от остального skaz-kray.ru.

## Структура URL

Публичное (без входа, PHP рендерит из одобренных записей):
- `/dnevniki-pomestiy/` — лента «Дневники поместий» с пагинацией
- `/dnevniki-pomestiy/{id}/` — страница отдельной записи
- `/yarmarka/` — «Ярмарка», карточки товаров/услуг
- `/yarmarka/{id}/` — страница товара

По входу (`/poselenie/`):
- вход / регистрация-заявка / восстановление пароля
- личный кабинет семьи (мои записи, мои товары, статусы модерации)
- панель модерации (только для роли «редактор»)

В шапке статического сайта добавляются пункты: «Дневники поместий», «Ярмарка»,
«Кабинет жителя».

## Модель данных (`skazkray_residents`)

- **`families`** — `id`, `email` (уникальный), `password_hash`, `name` (название
  семьи/поместья, показывается под записями), `status` (`pending`/`active`/`blocked`),
  `role` (`resident`/`editor`), `created_at`, `approved_at`.
- **`diary_entries`** — `id`, `family_id`, `title`, `body`, `status`
  (`pending`/`published`/`rejected`), `reject_reason`, `created_at`, `updated_at`,
  `published_at`.
- **`products`** — `id`, `family_id`, `title`, `description`, `price` (nullable —
  «по договорённости»), `contact`, `status` (те же), `reject_reason`, таймстемпы.
- **`images`** — `id`, `owner_type` (`entry`/`product`), `owner_id`, `path`, `sort`.
  И дневник, и товары могут иметь несколько фото.
- **`password_resets`** — `family_id`, `token`, `expires_at`.

Сессии — нативные PHP-сессии.

## Потоки

1. **Регистрация:** заявка → `pending` → редактор одобряет/отклоняет → `active`
   (+ письмо «добро пожаловать») или отказ.
2. **Новая запись/товар:** создаётся со статусом `pending` → очередь модерации →
   редактор одобряет (`published`, появляется в публичной ленте, семье письмо
   «опубликовано») либо отклоняет с причиной (`rejected`; семья видит причину в
   кабинете, исправляет и отправляет снова).
3. **Правка опубликованного** → возвращается на модерацию (`pending`). **Удаление**
   своей записи/товара — сразу, без модерации.
4. **Модерация (редактор):** единая панель-очередь — заявки на регистрацию, новые
   записи, новые товары; по каждому «одобрить» / «отклонить с причиной».
5. **Восстановление пароля:** запрос по email → письмо со ссылкой-токеном (ограничен
   по времени) → новый пароль. Страховка: редактор сбрасывает пароль вручную из
   панели, если письмо не дошло.

**Кабинет семьи:** свои записи и товары со статусами (на проверке / опубликовано /
отклонено + причина), кнопки создать / редактировать / удалить.

## Публичные страницы

- **«Дневники поместий»** — лента опубликованных записей с пагинацией: заголовок,
  отрывок, фото, подпись семьи/поместья, дата; клик → полная запись.
- **«Ярмарка»** — карточки: фото, название, цена (или «по договорённости»), семья,
  контакт; клик → страница товара.
- Рендерит PHP в вёрстке и токенах статического сайта.

## Безопасность

- Пароли — bcrypt (`password_hash`/`password_verify`).
- Все запросы к БД — подготовленные (PDO prepared statements).
- CSRF-токен на всех формах; cookie сессии `Secure` + `HttpOnly` + `SameSite`;
  только HTTPS.
- Загрузка фото: только изображения, лимит размера, пересохранение через GD/Imagick
  со снятием EXIF, хранение в отдельном каталоге без права выполнения скриптов.
- Простое ограничение попыток входа и регистрации (защита от перебора).
- Секреты (доступ к БД, SMTP) — в `config.php` вне git, права `640` (как существующий
  `oauth/config.php`).

## Деплой

- Отдельный каталог `/var/www/skaz-residents/`, свой `location` в nginx.
- Автодеплой статики приложение не трогает (оно вне докрута Astro).
- Каталог загруженных фото и `config.php` — вне git, переживают пересборки.
- Схема БД — SQL-миграция при установке; отдельная миграция при будущих изменениях.

## Проверка

Тест-раннера в проекте нет — верификация ручная в браузере:

- Сквозной прогон: регистрация → одобрение → вход → создание записи и товара →
  модерация → публикация → просмотр на публичной странице.
- Отклонение с причиной → правка → повторная отправка.
- Восстановление пароля (письмо + ручной сброс редактором).
- Правка опубликованного → возврат на модерацию.
- Удаление своей записи/товара.
- Тестовая семья и тестовый редактор для прогона.
