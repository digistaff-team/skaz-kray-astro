# Мобильный PWA «Сказочный Край» (v1) — дизайн

Дата: 2026-09-04
Репозиторий: `digistaff-team/skaz-kray-astro`, приложение `residents/` (прод: `/var/www/skaz-residents`)
Источник дизайна: проект Claude Design «Skaz-kray.ru мобильное приложение» (`4690a06a-…`), файл
`Мобильное приложение.dc.html`, экран **1a** (рабочий прототип).

## Цель

Превратить утверждённый макет в **настоящий PWA, интегрированный в приложение**: устанавливаемое
на телефон, офлайн-читаемое, в фирменном стиле. Точка входа — новая мобильная главная-лаунчер
`/poselenie/app`. Разделы переиспользуют существующие адаптивные страницы (кабинет, совет,
задачи, инструменты, книги, поездки, бюджет) — их заново НЕ рисуем.

## Утверждённые решения (брейншторм)

- **Архитектура — гибрид C**: новая мобильная server-rendered страница-лаунчер (PHP) в стиле
  макета + PWA-слой (`manifest` + service worker, офлайн-чтение). Действия идут через существующие
  контроллеры/маршруты — нового JSON-API нет, логика не дублируется.
- **Вход — по факту сессий**: лаунчер под `Auth::requireLogin()` (житель). Плитки/кнопки совета
  показываются только при активной council-сессии (`CouncilAuth::id() !== null`); иначе — кнопка
  «Войти как член совета» → `/sovet/vhod`. Две авторизации (`families` / `council_members`)
  остаются независимыми, но живут в одной оболочке. Аккаунты НЕ связываем (отдельная работа/риски).
- **Офлайн — только чтение**: SW кэширует оболочку/ассеты и последние отданные страницы; честный
  баннер «Сети нет…». Действия (взять/закрыть задачу, новая запись) требуют связи; фоновой очереди
  (Background Sync) в v1 нет — отдельная фаза.
- **Объём экранов**: только новый лаунчер; остальные экраны макета (кабинет, совет, задачи,
  направления) переиспользуют существующие страницы. Их «телефонные» версии 1:1 — вне v1.
- **Точка входа** `/poselenie/app`, ярлык в шапке жителей — «Приложение».

## Архитектура

Встраивается в существующее приложение (чистый PHP 8.3 + PDO, тонкий роутер, шаблоны-партиалы,
namespace `SkazResidents`, тесты на SQLite in-memory). Никакого JS-фреймворка: лаунчер —
server-rendered; клиентский JS — только регистрация SW и определение онлайн/офлайн. Стиль —
фирменные токены (`--green #008757`, `--ochre #c98a3a`, `--paper #fbfaf5`, PT Serif/PT Sans).

### Экран-лаунчер (`/poselenie/app`)

Точно по макету 1a (home), но данные живые. Гард `Auth::requireLogin()`.

Блоки сверху вниз:
1. **Шапка**: логотип поселения (52×52) + «Сказочный Край» (PT Serif, зелёный) + «Здравствуйте,
   {имя семьи}».
2. **Карточка «Ближайшее»**: заголовок собрания и дата/место из `CouncilData::nextMeeting()`,
   строка «N вопросов в повестке»; две кнопки: «Повестка» → `/sovet` (или гейт совета),
   «Мои задачи · {mineCount}» → `/sovet/zadachi` (только при council-сессии; иначе кнопка ведёт
   на вход в совет). Если council-сессии нет — карточка показывает собрание, а действия совета
   заменяются одной кнопкой «Войти как член совета».
3. **Полоска дневника**: статус последней записи семьи (например «1 запись на проверке» +
   заголовок) из `DiaryRepository` по `Auth::id()`. Если записей нет — «Дневник поместья пуст,
   добавьте первую запись» со ссылкой на создание.
4. **Сетка плиток «Разделы»** (2 колонки, ≥104px, ≥ссылки 56px): Дневник поместья (→ `/poselenie`),
   Попечительский совет (→ `/sovet` или гейт), Инструменты (→ `/poselenie/instrumenty`), Книги
   (→ `/poselenie/knigi`), Поездки (→ `/poselenie/poezdki`), Ярмарка (→ `/yarmarka`). Подписи —
   живые счётчики: свободных инструментов, книг на полке, поездок на неделе, задач совета в работе.
5. **Баннер офлайна** (скрыт по умолчанию, показывается клиентским JS при `navigator.onLine === false`
   или при отдаче из SW-кэша): «Сети нет. Показываем сохранённое, изменения уйдут при связи.»

Счётчики собирает сервис-агрегатор `AppDashboard` (только чтение) из существующих репозиториев —
единый источник, чтобы контроллер оставался тонким. Значения, недоступные дёшево, опускаются
(подпись без числа), не роняя страницу.

### PWA-слой

- **`manifest.webmanifest`** (отдаётся PHP-контроллером с `Content-Type: application/manifest+json`):
  `name`/`short_name` = «Сказочный Край», `start_url` = `/poselenie/app`, `scope` = `/poselenie/`,
  `display` = `standalone`, `theme_color` = `#008757`, `background_color` = `#fbfaf5`, `lang` = `ru`,
  иконки 192/512 (+ maskable) из логотипа поселения.
- **Service worker** (`/poselenie/sw.js`, scope `/poselenie/`):
  - precache: оболочка лаунчера-ассетов (`residents.css`, шрифты woff2, иконки, офлайн-страница).
  - runtime: навигационные запросы (`mode==='navigate'`) — network-first, при офлайне → кэш этой
    страницы, иначе → офлайн-страница; статика (css/woff2/png) — cache-first; POST и запросы вне
    scope — не перехватываются (уходят в сеть).
  - версионирование кэша по строке-версии; активация чистит старые кэши.
  - `/sovet/*` вне scope — в v1 работает онлайн, офлайн-кэш совета не входит.
- **Регистрация SW и manifest** подключаются в общий `templates/layout.php` (шапка жителей):
  `<link rel="manifest">`, `<meta name="theme-color">`, apple-touch-icon и инлайновый скрипт
  `navigator.serviceWorker.register('/poselenie/sw.js')`. Так вся зона `/poselenie/*` становится
  устанавливаемой и офлайн-читаемой, а не только лаунчер.
- **Отдача из PHP** (`PwaController`): маршруты `/poselenie/manifest.webmanifest` и `/poselenie/sw.js`
  с корректными MIME и без кэш-бастинга самого sw.js (заголовок `Cache-Control: no-cache` для sw.js).
  Иконки — статикой в `residents/public/icons/`. Правок nginx не требуется.

### Офлайн-баннер и статус

Клиентский скрипт (инлайн в лаунчере/партиале) слушает `online`/`offline` и показывает/прячет
баннер. Дополнительно SW может добавлять заголовок/помечать ответы из кэша — но для v1 достаточно
`navigator.onLine`. Время «сохранено на HH:MM» — момент рендера страницы (метка сервера).

## Данные и безопасность

- Новых таблиц нет. Счётчики — из существующих репозиториев (`CouncilTaskRepository`,
  `ToolRepository`, `BookRepository`, `TripRepository`, `DiaryRepository`) и `CouncilData`.
- 152-ФЗ: SW кэширует только страницы текущего пользователя (per-session), чужие ПДн в кэш не
  попадают; агрегатор не прокидывает идентификаторы в клиент сверх того, что уже на странице.
- Гарды: лаунчер — `Auth::requireLogin()`. Плитки/кнопки совета видны только при council-сессии.
  `manifest.webmanifest`/`sw.js`/иконки — публичны (не содержат ПДн).

## Обработка ошибок и краевые случаи

- Нет council-сессии → карточка «Ближайшее» и плитка «Совет» ведут на `/sovet/vhod` (кнопка
  «Войти как член совета»), задачи совета не показываются.
- Репозиторий-счётчик недоступен/пусто → плитка показывается без числа, не падает.
- SW не поддерживается браузером (старый) → страница работает как обычная (прогрессивное улучшение).
- Офлайн и переход по ссылке на некэшированную страницу → офлайн-страница SW с кнопкой «Повторить».
- `/sovet/*` при офлайне (вне scope) → обычная ошибка сети браузера (в v1 приемлемо, задокументировано).

## Тестирование

phpunit (SQLite in-memory, `php8.3`):
- `AppDashboard`: агрегатор счётчиков возвращает корректные числа и переживает пустые/отсутствующие
  данные (0/пропуск), не бросает.
- Гарды: гость на `/poselenie/app` → редирект на вход жителей; при council-сессии появляются
  council-действия (юнит на ветвление, где практично).
- Синтаксис новых PHP-файлов (`php -l`) и корректный MIME манифеста/sw (проверка контроллера).
Ручная проверка на проде: установка PWA на телефон, офлайн-режим (чтение из кэша + баннер),
переходы по плиткам, вход в совет из лаунчера.

## Деплой

- Схема БД не меняется — миграций нет.
- Доставка кода в `/var/www/skaz-residents` (git archive + tar, как в модуле бюджета) + `dump-autoload`
  + `systemctl reload php8.3-fpm`.
- Иконки — статикой в `public/icons/` (отдаются nginx). Маршруты `/poselenie/app|manifest|sw` идут
  через существующий front-controller — правок nginx не требуется.
- Пункт «Приложение» в шапке жителей — server-rendered PHP, пересборка Astro не нужна; `nav.js`
  (меню сайта) не трогаем.

## Файловая структура (ориентировочно)

Создать:

- `residents/src/Controller/AppController.php` — лаунчер `/poselenie/app`.

- `residents/src/templates/app/offline.php` — офлайн-страница (маршрут `/poselenie/offline`,
  прекэшируется SW и отдаётся при офлайне на некэшированную навигацию).
- `residents/public/icons/icon-192.png`, `icon-512.png`, `icon-maskable-512.png` (из логотипа).
- `residents/tests/AppDashboardTest.php`.

Изменить:
- `residents/public/index.php` — маршруты `/poselenie/app`, `/poselenie/offline`,
  `/poselenie/manifest.webmanifest`, `/poselenie/sw.js`.
- `residents/src/templates/layout.php` — `<head>`: manifest/theme-color/apple-touch-icon +
  регистрация SW; пункт «Приложение» в шапке жителей.
- `residents/public/assets/residents.css` — стили `.app-*` (лаунчер) из макета.

## Явно вне объёма (YAGNI / отдельные фазы)

- Офлайн-запись через Background Sync (очередь действий) — фаза 2.
- Телефонные версии экранов Кабинет/Совет/Задачи/Направления 1:1 с макетом — переиспользуем текущие.
- Офлайн-кэш раздела `/sovet/*` (SW scope только `/poselenie/`).
- Связывание аккаунтов `council_member ↔ family` (единый вход) — отдельная работа.
- Push-уведомления.
